## 1. 背景与问题定义

实验需要把"逐行手写代码"换成"用结构化意图驱动 AI 生成，再由人做审查与验证"的工作流。本任务取一个最小但完整的垂直切片：**静态 HTML 列表页 → 四字段结构化数据 → CSV**。

选它的原因：列表页是绝大多数采集任务的入口形态，字段固定、结构可预测，能把注意力从"网页长什么样"转移到"需求写得够不够清楚、验证做得够不够硬"。

基础任务要解决的三个真实问题：

1. **意图模糊**导致 AI 输出不可验收——"帮我写个爬虫"必然返工。
2. **一次性生成**导致报错无从定位——几十行一起错，Traceback 指不到根因。
3. **AI 代码不可信**——默认没有重试、没有间隔、没有异常兜底，跑通一次不等于能跑一百次。

## 2. 目标与非目标

### 2.1 目标（Goals）

| 编号 | 目标 | 判定方式 |
| --- | --- | --- |
| G1 | 打通"列表页 → 字段 → CSV"完整链路 | 生成 `result.csv`，行数 = 页面条目数 |
| G2 | 建立可复用的结构化 Prompt 模板 | 四要素齐全，能直接交给 AI 执行 |
| G3 | 体现分步生成与最小化验证 | 过程记录中含 ≥3 次"生成 → 运行 → 反馈"闭环 |
| G4 | 完成面向对象重构且功能不退化 | 重构前后 CSV 内容一致（逐行 diff 为空） |

### 2.2 非目标（Out of Scope）

- 不处理登录、验证码、付费墙、需鉴权的接口。
- 不处理 JavaScript 动态渲染（→ 见《需求文档 02 · 进阶挑战》）。
- 不做分布式调度、代理池、持久化数据库、定时任务。
- 不做数据清洗之外的语义分析（分类、摘要、情感）。

## 3. 角色与协作方式

| 角色 | 承担者 | 职责 |
| --- | --- | --- |
| 需求方 | 学生本人 | 写清意图、定义验收线、判定"是否通过" |
| 实现方 | AI 编程助手 | 按 Prompt 产出代码，按 Traceback 修 bug |
| 审查方 | 学生本人 | 逐段读代码、质疑默认值、砍掉多余抽象 |

**核心纪律**：需求方与审查方不能是"甩手掌柜"。判定标准只有一条——**你能不能向别人解释这段代码每一行为什么存在**。

### 3.1 四拍循环

```
第 1 拍 意图定义：角色 + 目标 + 约束 + 验收标准，一次只描述一个模块
第 2 拍 任务拆解：把需求切成 请求 / 解析 / 持久化 / 重构 四个可独立验证的单元
第 3 拍 生成验证：只让 AI 生成当前单元，立刻本地运行，打印中间态
第 4 拍 报错反馈：原样贴 Traceback + 相关代码片段 + 期望行为，要求最小改动
```

## 4. 结构化 Prompt 规范

### 4.1 四要素模板

```text
【角色】你是 Python 后端工程师，熟悉 requests 与 BeautifulSoup 的工程实践。
【目标】编写静态网页爬虫，抓取 [TARGET_URL] 列表页，提取标题、发布时间、作者、详情页链接。
【约束】
  - 仅使用 requests + beautifulsoup4（解析器 lxml），不引入 Selenium/Playwright；
  - 必须设置真实浏览器 User-Agent，并携带 Referer；
  - 相邻两次请求间隔 ≥ 2 秒；
  - 单次请求超时 10 秒，超时/5xx 最多重试 3 次，退避 2s/4s/8s；
  - 只输出本步骤所需的最小代码，不要提前写 CSV 与类结构。
【验收】终端打印 HTTP 状态码、HTML 长度、前 3 条解析结果；字段缺失填空字符串不抛异常。
```

### 4.2 模糊 Prompt 与结构化 Prompt 的差异

| 维度 | 模糊版 | 结构化版 |
| --- | --- | --- |
| 输入 | "帮我写个爬虫" | 站点、字段、库、限速、重试、验收全部给定 |
| AI 输出 | 一次性 200 行，含未要求的代理池与多线程 | 单模块 20–40 行，边界清晰 |
| 返工次数 | 3 次以上，且每次都要重读全量代码 | 1–2 次，改动范围可预测 |
| 可验收性 | 无（"跑起来没报错"即通过） | 有（状态码、条数、编码、列序可核对） |

### 4.3 单模块 Prompt 示例（第 2 步：解析层）

```text
【增量任务】在已跑通的 fetch 函数基础上，新增 parse_list(html) 函数。
【要求】返回 list[dict]，每条含 title/time/author/url 四个键；
        用 CSS 选择器定位，选择器写成模块级常量便于替换；
        相对链接用 urljoin 补全为绝对地址；
        time 统一为 YYYY-MM-DD，无法识别时保留原始文本；
        任一字段取不到时填空字符串 ""，不得抛异常。
【验收】打印前 3 条完整字典；对空 HTML 返回 []，对残缺条目仍返回 dict。
```

## 5. 功能需求清单

### 阶段 A · 请求层（FR-A）

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| FR-A1 | 使用 `requests.Session` 发起 GET 请求 | P0 | 复用连接，UA/Referer 挂在 Session 头 |
| FR-A2 | 设置浏览器 User-Agent + Accept-Language | P0 | 打印请求头可见 |
| FR-A3 | 超时时间 10 秒（connect/read 分别设置） | P0 | 断网时 10 秒内抛 `Timeout`，不无限挂起 |
| FR-A4 | 失败重试 3 次，指数退避 2s/4s/8s | P0 | 日志中出现 3 条重试记录后放弃 |
| FR-A5 | 显式设置 `response.encoding`（或 `apparent_encoding`） | P0 | 中文不乱码 |
| FR-A6 | 相邻请求间隔 ≥ 2 秒 | P0 | 两次请求时间戳差值可验证 |
| FR-A7 | 状态码非 200 时记录并跳过，不中断整体 | P1 | 返回 `None` 并写日志 |

### 阶段 B · 解析层（FR-B）

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| FR-B1 | 用 CSS 选择器提取列表条目，选择器外置为常量 | P0 | 换站点只改常量区 |
| FR-B2 | 提取 4 字段：标题 / 时间 / 作者 / 链接 | P0 | 每条 dict 键齐全 |
| FR-B3 | 相对链接经 `urljoin` 转绝对链接 | P0 | 输出以 `http` 开头 |
| FR-B4 | 时间归一化为 `YYYY-MM-DD` | P1 | 无法解析时保留原文，不抛异常 |
| FR-B5 | 标题去首尾空白、压缩内部连续空白 | P1 | 无 `\n`、无多重空格 |
| FR-B6 | 单条解析失败仅跳过该条，记录原因 | P0 | 异常计数 ≤ 条目数且程序正常结束 |
| FR-B7 | 空页面 / 选择器失配返回 `[]` | P0 | 不抛 `AttributeError` |

### 阶段 C · 持久化层（FR-C）

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| FR-C1 | 写入 `result.csv`，编码 `utf-8-sig` | P0 | Excel 直接打开无乱码 |
| FR-C2 | 列顺序固定为 `title,time,author,url` | P0 | 表头逐字一致 |
| FR-C3 | 缺失字段写空字符串，不写 `None`/`nan` | P0 | `grep -c "None"` 为 0 |
| FR-C4 | 按 `url` 去重（保留首次出现） | P1 | 重复链接只留 1 行 |
| FR-C5 | 终端打印成功抓取条数 | P0 | 格式：`成功抓取 N 条` |
| FR-C6 | 使用 `csv` 模块或 `pandas.to_csv(index=False, quoting=...)` | P2 | 含逗号/换行的标题不串列 |

## 8. 反爬合规约束（硬约束，违反即判不通过）

1. 抓取前读取 `[TARGET_URL]/robots.txt`，`Disallow` 路径一律不碰。
2. 只抓公开可匿名访问的列表页与详情页，不绕过登录、验证码、付费墙。
3. 请求间隔 ≥ 2 秒，单次实验总请求数 ≤ 50；不使用并发。
4. 不采集任何个人隐私字段（手机号、身份证、住址、账号）。
5. 不将数据用于再发布、商业分发或训练语料；仅用于本实验的分析与报告。
6. 不伪造 Cookie/Token 冒充登录态，不修改请求签名。
7. 站点出现 `429 / 403` 立即停止，不换 IP 硬撞。
8. 实验结束后清理原始 HTML 缓存，仅保留聚合后的 CSV 与统计结果。

## 9. 验收标准（AC）

| 编号 | 验收项 | 通过条件 | 证据 |
| --- | --- | --- | --- |
| AC-1 | 请求跑通 | 打印 `status=200`，`len(html) > 10000` | 终端截图/日志 |
| AC-2 | 解析正确 | 前 3 条四字段人工核对与网页一致 | 终端打印 + 网页对照 |
| AC-3 | 条数吻合 | CSV 行数 = 页面条目数（±0） | `wc -l result.csv` |
| AC-4 | 编码正确 | UTF-8-SIG，Excel 打开中文正常 | 文件属性 + 打开截图 |
| AC-5 | 列名对齐 | 表头为 `title,time,author,url` | CSV 首行 |
| AC-6 | 缺失兜底 | 人为删掉一条的作者节点，程序不崩且该格为空 | 变异测试记录 |
| AC-7 | 限速生效 | 两次请求间隔 ≥ 2s | 时间戳日志 |
| AC-8 | 重试生效 | 指向 `http://httpbin.org/status/500` 时重试 3 次后退出 | 重试日志 |
| AC-9 | 重构不退化 | 重构前后 CSV `diff` 为空 | `diff old.csv new.csv` |
| AC-10 | 结构达标 | `NewsCrawler` 四方法齐全，`run()` 可一键跑完 | 代码文件 |

### 9.1 变异测试（必做，防"假通过"）

- 删掉 1 条记录的 `author` 节点 → 期望：该格 `""`，其余行正常。
- 把选择器改成 `.not-exist` → 期望：返回 `[]`，打印 `成功抓取 0 条`，退出码 0。
- 把 URL 改成 `http://10.255.255.1/` → 期望：10 秒超时、重试 3 次、正常退出。

| 里程碑 | 交付内容 | 通过标志 | 建议耗时 |
| --- | --- | --- | --- |

## 13. 代码审查清单

逐项打勾，任何一项为"否"都不算完成：

- [ ] `timeout` 是否真的传给了 `requests.get`，而不是写在注释里？
- [ ] 重试是循环实现还是 `HTTPAdapter`？循环版是否会重试 4xx（不该重试）？
- [ ] `response.encoding` 是否显式设置？依赖 `r.text` 默认值在 GBK 站点会乱码。
- [ ] 解析是否用了 `find(...).text` 这种"节点不存在就崩"的写法？是否改用 `select_one` + 判空？
- [ ] `urljoin` 的 base 是列表页 URL 还是站点根？相对路径 `./a.html` 在两者下结果不同。
- [ ] CSV 是否漏了 `newline=""`？Windows 下会产生空行。
- [ ] 是否有 AI 擅自加的多线程/代理池/随机 UA 库？——不需要就删掉。
- [ ] 类里是否有 `self.html` 这类跨方法传递的隐式状态？能否改成参数传递？
- [ ] 日志里是否含完整 URL？含敏感 query 的要去掉。

## 14. 风险与对策

| 风险 | 触发信号 | 对策 |
| --- | --- | --- |
| 选择器失配 | 解析条数为 0 但 HTML 正常 | 先 `print(soup.prettify()[:2000])` 看真实结构，再定选择器 |
| 编码乱码 | 中文变 `æ–‡ç« ` | 显式 `r.encoding = r.apparent_encoding` |
| 被限流 | 403 / 429 / 返回验证码页 | 立即停止，降频到 5 秒，只抓首页验证 |
| AI 过度设计 | 生成 300 行含未要求功能 | Prompt 加"只输出本步骤最小实现"，多余代码直接删 |
| 跳步导致错误叠加 | M3 报错但根因在 M2 | 回退到上一里程碑，用固定 HTML 离线调试解析 |
| 假通过 | 跑通一次就交 | 执行第 9.1 节三个变异测试 |

## 15. 与进阶任务的衔接

基础任务交付后，保留以下三样东西，进阶任务直接复用：

1. `NewsCrawler` 的类结构（进阶版继承或替换 `fetch` 一层即可）。
2. CSV 写入与去重逻辑（两种方案共用）。
3. 限速与重试策略（动态渲染方案同样需要）。

字段定义、CSV 列序、验收口径在进阶任务中**保持不变**，只替换"如何拿到 HTML"这一层，这样才能做同口径的性能对比。
