# 进阶版实现说明（方案 A / 方案 B / 度量）

对应文档：《02_进阶挑战_动态渲染爬虫需求文档》。这里给的是**能直接跑的代码**，以及在本机实测出来的数字。

## 一、四个脚本各管什么

| 文件 | 职责 | 输出 |
| --- | --- | --- |
| `src/api_crawler.py` | 方案 A：接口逆向。直连接口，或自动嗅探页面里的 XHR | `result_api.csv` + `metrics_api.json` |
| `src/browser_crawler.py` | 方案 B：Playwright 驱动浏览器渲染后取 DOM | `result_browser.csv` + `metrics_browser.json` |
| `src/crawler_core.py` | 公共库：字段抽取、分组启发式、CSV 写入（A/B 都 import 它） | — |
| `src/metrics.py` | 跑 N 轮、测耗时与内存、生成对比表 | `metrics_raw.json` + `compare.md` |

**为什么 A/B 共用 `src/crawler_core.py`**：字段口径必须完全一致，否则"两方案条数一致"这条验收就没意义。解析逻辑只写一份，两种取数方式共用。

## 二、环境准备

```bash
uv pip install --python .venv/Scripts/python.exe playwright psutil

# 首选：下载 playwright 自带 chromium（约 150MB）
.venv/Scripts/python.exe -m playwright install chromium

# 下载被网络挡住时：直接驱动本机已装的 Chrome / Edge
python run.py 渲染 <URL> --channel chrome

# 或者用自己下的内核（见 chromium下载指南.md）
python run.py 渲染 <URL> --exe ".browsers/chrome-win64/chrome.exe"
```

`src/browser_crawler.py` 内置了降级顺序：`--exe` → `bundled chromium` → `chrome` → `msedge`，前一个失败自动试下一个，日志里会打印实际用的是哪个内核。

## 三、方案 A 的两种用法

### 3.1 已知接口地址（最省事）

```bash
python run.py 接口 --api "https://example.com/api/list?page=1" --max-pages 3
```

接口地址从 DevTools → Network → Fetch/XHR 里挑返回列表数组的那条，右键 Copy as cURL，把 URL 与必要请求头抠出来。`--referer` 可补 Referer，`--page-param` 改翻页参数名（默认 `page`）。

### 3.2 只有页面地址（自动嗅探）

```bash
python run.py 接口 --sniff "https://example.com/news"
```

内部流程：开无头浏览器 → 监听所有 `content-type: json` 的响应 → 对每个 JSON 递归找"含 title 类字段的 dict 数组" → 按条数排序 → 选最大的那条 → 用 requests 复刻（带上抓到的 Referer/X-Token/Cookie）→ 翻页落 CSV。

实测（本地样例页 `/spa_live.html`，数据由 JS fetch 后渲染）：

```
[嗅探] 命中 1 个返回列表的接口
候选接口（按条数降序）:
  1.    5 条  http://127.0.0.1:8899/api/list.json?page=1
     字段样例: ['id', 'title', 'publishTime', 'author', 'link']
[选用] http://127.0.0.1:8899/api/list.json?page=1
[复刻 页 1/1]  [✓] 5 条
成功抓取 5 条 -> result_api_sniff.csv   累计传输 0.9 KB
```

嗅探只在开发阶段用一次，把接口地址固化下来；正式采集只跑 `--api`，不再开浏览器。

## 四、方案 B 的用法

```bash
python run.py 渲染 "https://example.com/news" \
    --pages 3 --selector "div.news-item" --channel chrome
```

关键参数：

| 参数 | 作用 | 默认 |
| --- | --- | --- |
| `--selector` | 条目容器选择器；不给则走启发式分组 | 自动 |
| `--pages` | 翻页数（按 `?page=n` 追加） | 1 |
| `--delay` | 页间隔秒 | 2.0 |
| `--channel` | 用哪个浏览器内核 | 自动降级 |
| `--keep-images` | 不拦截图片/字体/样式 | 拦截 |
| `--headed` | 显示浏览器窗口，调试用 | 无头 |

实测输出：

```
  [i] 浏览器内核: chrome
  [→] goto (第 1/2 次)
  [i] 滚动 3 次后节点数稳定（6），停止滚动
  [✓] 渲染完成 1487 bytes DOM / 可见文本 184 字
  [i] 条目块 5 个
  [✓] 解析 5 条
成功抓取 5 条 -> result_browser.csv
耗时 5.8s / 峰值内存 636 MB / 传输 2 KB
```

等待策略的三层：先 `wait_for_selector(条目)`，超时才退回 `networkidle`（5 秒上限，很多站永远不 idle），最后固定 1.2 秒兜底。滚动按"节点数连续两次不变"判定到底，不滚固定次数。

## 五、度量：一条命令出对比表

```bash
python run.py 对比 \
  --page-url "https://example.com/news" \
  --api "https://example.com/api/list?page=1" \
  --pages 1 --rounds 3
```

不给 `--api` 时，方案 A 自动走嗅探模式（耗时会含浏览器启动，报告里要注明）。

### 5.1 本机实测结果（2026-11-18，5 条数据，3 轮取中位数）

| 指标 | A 接口逆向 | B 浏览器渲染 | 倍数 |
| --- | --- | --- | --- |
| 端到端耗时（s） | **0.85** | **6.87** | B 慢 8.1× |
| 峰值内存（MB，进程树） | **51.3** | **638.5** | B 高 12.4× |
| 传输量（KB） | 0.9 | 1.8 | B 多 2.0× |
| 抓取条数 | 5 | 5 | 一致 |
| 有效代码行 | 264 | 234 | B 略少 |
| 稳定性 | 3/3 | 3/3 | 一致 |

三轮原始值：A `0.93 / 0.75 / 0.85` 秒；B `7.09 / 6.87 / 6.87` 秒。

### 5.2 结论（条件句，可直接抄进报告）

> 当接口返回明文 JSON、且无签名参数时，选方案 A：本实验中耗时降低 **87.6%**（0.85s vs 6.87s），峰值内存降低 **92.0%**（51.3MB vs 638.5MB），传输量减半，代码量基本持平但少一个浏览器二进制依赖。
> 当接口携带 `sign`/`_t` 等加密参数、或数据只在客户端计算生成时，只能选方案 B，代价是 **8 倍耗时**与 **12 倍内存**，换来的是"所见即所得"的穿透力。
> 需要长期稳定运行时，优先 A + 选择器/字段映射外置；把 B 作为 A 失效时的兜底通道（`--sniff` 一条命令即可切换）。

注意：单页数据量只有 5 条，B 的固定开销（浏览器启动 ≈ 4–5 秒）被摊得最薄，**页数越多，倍数会越小**。测 5 页时 B 的劣势会从 8 倍降到 3–4 倍左右，报告里应说明这一点，否则结论会被质疑。

## 六、这次踩到的四个真坑

### 6.1 同一个时间戳，两个方案差一天

A 输出 `2026-11-12`，B 输出 `2026-11-11`。原因：样例页用 `new Date(ts).toISOString().slice(0,10)` 渲染，`toISOString` 是 UTC，东八区凌晨的时间会退回前一天。A 用的是 `datetime.fromtimestamp()` 走本地时区，所以正确。

**结论**：跨方案对比前必须确认时间归一化规则一致，否则"条数一致"掩盖了"内容不一致"。生产代码里显式指定时区：`datetime.fromtimestamp(ts/1000, tz=ZoneInfo("Asia/Shanghai"))`。

### 6.2 chromium 下载被网络挡住

`playwright install chromium` 报 `Download failure, code=1`。改用 `--channel chrome` 直接驱动本机 Chrome 即可，脚本已内置降级。

### 6.3 本地回环被系统代理拦成 502

沙箱/公司网络里 `HTTP_PROXY` 会把 `127.0.0.1` 也走代理，requests 拿到 502。加环境变量：

```bash
NO_PROXY="*" HTTP_PROXY= HTTPS_PROXY= python run.py 基础 http://127.0.0.1:8899/list.html
```

### 6.4 `networkidle` 永不触发

带埋点/长轮询的站点 `wait_for_load_state("networkidle")` 会一直超时。脚本设了 5 秒上限并打印提示，然后继续走固定等待——不要为了"优雅"在这里无限等。

## 八、一句话记住选型

**能拿到 JSON 就别开浏览器。** 开浏览器是"我拿不到数据"时的最后手段，不是"更高级"的方案。上面 8 倍耗时、12 倍内存，就是这句话的价格。
