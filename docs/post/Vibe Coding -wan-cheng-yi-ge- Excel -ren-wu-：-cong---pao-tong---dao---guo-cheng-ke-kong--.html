Vibe Coding 完成一个 Excel 任务：从"跑通"到"过程可控"

引言：Vibe Coding 到底在考什么？

最近做了一次 Vibe Coding 实操考核：用自然语言指挥 AI 编码工具完成一个 Python 任务。题目本身很简单——读一张 Excel 销售表，清洗脏数据，统计销售额，输出报表。如果只看功能，几分钟就能让 AI 一口气写完。

但考核的评分维度不是"代码多漂亮"，而是结果、过程、验证、风险、复盘五个维度。真正拉开差距的，是你如何把任务拆开、如何管理 AI、如何在每个节点验证。一句话：别让 AI 一口气把活干完，然后甩给你一句"跑通了"。

这篇博客记录我完整的实操过程，从需求澄清到最后复盘，共拆成 8 个可独立验证的步骤。

一、先澄清需求，再让 AI 动手

把考题原文丢给 AI 之前，我先让它整理了一份《需求澄清清单》，逐项写清：

项 内容
目标 读 sales_raw.xlsx，清洗 + 统计，输出 report.xlsx
输入 字段：日期、销售员、产品、数量、单价、地区（含脏数据）
输出 4 张表：明细清洗后 / 按销售员 / 按地区 / 总览
清洗规则 删关键字段缺失行、剔数量≤0、全字段去重
统计口径 销售额 = 数量 × 单价；按销售员/地区汇总 + 月度总额
边界 缺失字段、空文件、无有效数据要报错不崩溃
验收 一键运行、数值与人工核对一致、异常不崩溃

人工接管点：考题里"关键字段"没有明确定义，我拍板默认日期/销售员/产品/数量/单价（排除地区），并在后续步骤验收时复核。这个决策 AI 替不了，必须人来定。

二、拆解：把大任务变成可验证的小步

我把整个任务拆成 7 个能单独运行、单独验证的步骤：

S1 样例数据 → S2 读取清洗 → S3 统计 → S4 输出报表
          → S5 异常处理 → S6 测试 → S7 一键运行+README

关键原则：每一步都有可见的中间产物（文件或打印），不必等全部完成就能验证。

三、逐步入场：每步一小块，跑通再进下一步

S1 构造样例脏数据

让 AI 生成 20 行数据，故意包含空值、0/负数量、整行重复：

rows = [
    ("2026-09-01", "张三", "咖啡", 10, 25, "华东"),   # 正常
    (None,         "李四", "绿茶", 10, 15, "华南"),     # 空日期
    ("2026-09-07", "王五", "饼干", 0, 12, "华北"),      # 数量=0
    ("2026-09-08", "张三", "果汁", -5, 18, "华东"),     # 负数量
]

验证：独立回读文件，确认脏数据齐全（空日期 1、空销售员 1、数量≤0 2、重复 2）。

S2 读取 + 清洗

实现三条清洗规则，并把每一步删了多少行打印出来：

df1 = df_raw.dropna(subset=KEY_FIELDS)   # 删关键字段缺失行
df2 = df1[df1["数量"] > 0]               # 剔数量≤0
df3 = df2.drop_duplicates()              # 全字段去重

验证：原始 20 → 删缺失 2 → 剔非正数 2 → 去重 2 → 清洗后 14，与人工预期完全一致。

S3 统计逻辑

销售额 = 数量 × 单价，按销售员/地区汇总 + 月度总额。

验证（人工抽算）：

  • 张三 = 250+75+300+120+120 = 865
  • 李四 = 160+360+120+360+40 = 1040
  • 王五 = 270+200+450+500 = 1420
  • 月度总额 3325，且 销售员合计 = 地区合计 = 3325，口径对得上。

S4 输出 report.xlsx

四张工作表：明细清洗后 / 按销售员 / 按地区 / 总览。
验证：独立回读文件，四表存在、数值与 S3 打印一致。

S5 异常处理

覆盖 4 类坏输入，全部给可读报错、脚本不崩溃：

[读取失败] 找不到原始文件: ...
[空文件] 原始文件 empty.xlsx 为空, 无任何数据行
[无有效数据] 清洗后无有效记录(关键字段缺失或数量<=0)

S6 测试用例

用 pytest 写 1 个正常 + 5 个边界/异常用例：

def test_normal_real_sample():
    df, c = load_and_clean(DEFAULT_RAW)
    assert c["清洗后行数"] == 14
    _, _, _, total = compute(df)
    assert total == pytest.approx(3325.0)

验证：pytest -v → 6 passed。

S7 一键运行 + README

统一入口 + requirements.txt + README.md：

清洗完成: 原始 20 -> 有效 14 行
月度销售额总额: 3325.00
报表已输出: ...\exam1\report.xlsx

四、一次真实的 bug：模块导入路径

S7 一键运行时报错，这是本轮最有价值的一段：

from scripts.stats import compute
  → scripts/stats.py → from clean import ...
ModuleNotFoundError: No module named 'clean'

根因：单独运行 python scripts/stats.py 时，scripts 目录会自动进搜索路径；但从根目录用包方式导入时，stats.py 内部的 from clean import ... 就找不到 clean 了。

修复：在统一入口 main.py 里把 scripts 目录加入搜索路径：

import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).resolve().parent / "scripts"))
from clean import DEFAULT_RAW, load_and_clean

教训：AI 生成的代码"单独能跑"不等于"一键能跑"，必须在真实入口验证——这正是"过程可控"的意义。

五、复盘：交 AI、自己拍板、人工审查

交给 AI：代码实现、数值计算、测试编写、README 骨架。

自己拍板：

  1. 关键字段的口径默认；
  2. 每次 AI 输出后独立抽算、回读，不轻信 AI 自报；
  3. 导入 bug 的根因定位与修复方式。

人工审查的风险：

  • 数据一致性（销售员合计 = 地区合计 = 总额）
  • 不改原始文件
  • 异常输入不崩溃
  • 统计口径（销售额强制 数量×单价）
  • 依赖环境固化（requirements.txt）

对照五维评分：结果（四表正确）／过程（8 小步+即时验证）／验证（抽算+回读+pytest+异常演示）／风险（四类人工审查）／复盘（本段）。

结语：Vibe Coding 的精髓是"管得住"
